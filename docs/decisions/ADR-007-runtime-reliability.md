# ADR-007：A-D07只修运行边界，不调冻结参数

依赖B-D06分支codex/B-D06-protocol、提交c84e8334d681a86151cfa63b22a2307dd0245963。采用v0.2技术候选，不将其当作已通过联合G2的正式协议。Owner成员A；执行Codex Agent A；实际机器糯糯；计划10月21日、实际从10月19日开始。精确模型unknown。

## 决定和可定位修复

1. **完整目标判定**：原relay_v2.calculate对B1只检查route_audit.valid，空路线在未覆盖目标时也可得到FEASIBLE。这是调用点误用，不是合法性检查器应把所有部分路线判非法。新runtime_d07.validate_method_result统一要求valid且goal_complete；Ours/B1/B2规则相同。非法/未覆盖保留为方法失败，不增加模型语义修复调用。原B文件不改，由A的StableRelayCollector和serve_d07新入口启用。
2. **可恢复错误**：safe_remaining对错误画像/不一致聚合/重复或跨人证据明确INVALID_INPUT，源文件无法访问为SOURCE_UNAVAILABLE；NO_FEASIBLE_FOUND、TIMEOUT保持区别，不签全局最优或无解证明。错误输出不包含任意异常消息或模型凭据。跨项目和相似字符串不自动合并证据。
3. **完整前缀与版本**：完成材料仍作覆盖，不是掌握；反馈扣题费一次，保留完成项。新事件同时保留B父引擎版本和A运行边界版本。新源码单独快照为A-D07-runtime-v1；原A/B冻结快照、阈值.7、q=.1、W16、成本、预算100、alpha/gamma=0不变。
4. **可见依据**：新增A页面显示路线单元、各项代理费用、固定源码commit/行号及目标/先修关系。这是可核对的材料依据，不冒充模型解释或最优性证明；三方法获得同类信息。暂停/测验/独立提交阶段隐藏该面板。浏览器发现的提交面板残留是本轮增强引入的回归，已修复；before/after AX证据保留。
5. **旧运行影响**：新版本改变“合法但不完整”的接收结果，不重写历史记录。对B-D06-v2-live01保存的三方法初始/反馈共6条路线另行重放；具体完整性结果见protocol-review-final.json。保留历史调用费用，不付费重跑。新正式数据必须选定并批准新版本，不直接用旧B入口绕过新guard。

## 任务、三方法和冻结审查

公开源与跨度、共同预算/测验、计时和独立评分边界均做技术核对，未打开私有终测答案。12题为4开发/8跨模块候选，不是24道已批准题，更不是两个仓库；人类题目/教学关系/难度批准仍未发生。task001/002保留旧A单元，不含新source.function目标，不能按通用policy字符串声称全部12题都新增了该约束。模型alias也不等于锁定不可变权重。

当前未知画像下，12题每个单元都含不可由其他单元替代的目标；其中4题仅一个单元。内容选择优化空间受限，不能将以后任务差异自动归因于“更优集合覆盖”。运行/顺序或整体方法价值仍可研究，但效果尚未验证。不为造优势而增删测试材料、改成本或调阈值。

Beta(1,1)未知先验在一次通过后为Beta(2,1)，q=.1下界sqrt(.1)≈.316<.7。一次失败更低；现行共同短测不会打开掌握门控。72个明确夹具闭环的反馈后余路线也都不变；完成项从队列移除不能冒充反馈修复收益。C2在本协议下不可据此证实，不宣传诊断/反馈提升。F09只在明确的模拟独立既有历史条件下展示失败后补回材料，不能冒充真实人效果。

开发01曾把“单次通过下界”元数据手写成失败分支公式；实际门控始终用冻结计算器，路线未受影响。原始元数据与源码保留，新增闭式公式回归；最终使用development05及其输入hash，不偷偷覆盖01。
