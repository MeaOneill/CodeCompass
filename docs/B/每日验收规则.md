# B每日交付与严格验收规则

来源：成员B用户2026-10-16新增要求，自B-D02起持续适用。每轮交接必须引用本规则，接任B的Agent先读。

沟通补充：用通俗话先说明用户现在需要做的一步；软件自验、题目质量审核和参与者实验必须分开。不把原始JSON交给用户充当易读任务说明，不要求用户临时学习知识或解编程题来补Agent开发验收。新增验收条件须有原任务卡依据，Agent自行设定的保守条件必须标明，不能冒充用户要求。

每天提供能打开的累计成果入口，标清已实现/已运行、仅设计、未完成。没有GUI时给实际CLI命令、预期关键输出和可查看原始文件；GUI可运行后再提供启动地址和逐步操作验收，不能用线框图冒充可用界面。自验指南从工作目录、环境开始，明确输入、观察点、失败后的下一动作。

收尾必须严格复检：复跑适用旧测试及新功能，使用错误/边界/超时/缺失依赖验证，不只测试成功夹具；检查源码版本/hash、共享接口、答案/用户数据边界、图表来源、Git显式文件和远程SHA。可由Agent修复的直接修复并保留失败，不把修复前结果删除。Agent自审、人类独立审核、真人预演分别记录。

业务门禁与同步门禁分开：推送成功不等于任务通过。自动化通过但人工必要项、任务规模或关键接口未完成时，写明未通过项及能推进的具体子步骤，不能无条件说“可进入下一日”。整体审核通过时明确说“允许进入下一步”，并注明下一棒任务及首动作。不得伪造审核、参与者、时长或效果。
