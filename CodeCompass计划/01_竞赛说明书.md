# CodeCompass V6.0 竞赛研究与开发说明书

## 1. 结论与项目定位

作品申报名建议：**开源代码学习与贡献导航**（11字）；内部名称 CodeCompass。申报方向：AI 开发工具与开源协作。服务对象先限定为具有 Python 基础、需要理解陌生开源项目局部功能的学生。

唯一主线：**根据个人实际能力、项目结构、代码学习难度与任务目标，联合规划内容选择和学习顺序。** 任务相关内容筛选、个性化前置闭包成本和联合约束搜索是主算法；诊断与反馈重规划是候选增强机制，不替代主线。

最终闭环：固定版本开源仓库 → 任务选择 → 短测 → 可追溯学习路径 → 阅读和独立测验 → 能力更新与重规划 → 长期记录 → 真实 Issue 的贡献准备建议。

采纳用户原则：至少有一项真实、可复现、有合理基线与错误分析的路径对照；五个模块是技术结构，不能强行包装为五个原创算法；复赛评价所需核心成果在首次提交前完成。完整意味着闭环、证据和复用完整，不以复杂度、模块数量或模型规模衡量。

## 3. 创新判断与相关工作边界

“不必创造从未有人做过的基础算法”这个判断与本赛道适度创新的要求一致；但“评委可能不知道”不能替代差异论证。目标是清楚说明对已有方法做了什么可测量的实质改进。

已核对的研究摘要：
- [KnowLP，2025](https://arxiv.org/abs/2506.22303)：GraphRAG生成前置/相似关系结构并服务于个性化学习路径。故“图谱+路径”不能直接称原创。
- [U-GLAD，2026预印本](https://arxiv.org/abs/2604.14613)：将认知不确定性和目标适配用于路径推荐。故“不确定性+个性化”不能直接称原创。

这里只完成摘要级排重，未完成系统查新或复现。D02必须核对全文、代码、数据适用性，形成“已有机制/我们的差异/验证办法”矩阵。不得宣称首创、SOTA或无人研究。

候选实质贡献：**在源码证据与经审核前置依赖上，统一比较“直接补学”和“先做诊断再决定跳过”的预算代价，并限制反馈后路径变化，减少误跳前置知识和无效反复学习。** 各个组成方法已有基础，本项目的任务建模、决策规则、实现和实证是待验证贡献。若短测不支持诊断选择，保留证据门控规划作为主贡献，诚实删去不成立部分。

## 4. 主算法的可执行设计

### 4.1 输入与图结构

- 仓库固定 commit；源码节点保留文件、行号、内容哈希。源码导入/调用关系与教学前置关系分开存储，调用关系不自动等于学习先修关系。
- 学习单元可组合函数、解释和一个知识点；只对人工审核必要关系施加硬前置约束。模型提议关系记录来源/不确定性，只作候选或软提示。
- 知识依赖有环时先人工审查；确属共同学习单元时折叠为单元簇并记录理由，不随意删除边。
- 任务目标知识集合 K_T、预算 B、用户按知识点的证据状态 U。单位成本在没有校准前称“代理成本”，不得标为分钟。

### 4.2 能力证据与跳过门控

首选可解释的 Beta-Bernoulli 证据模型：每个知识点保存 a_k、b_k 和独立题目ID；通过/失败更新一次。m_k=a_k/(a_k+b_k)，l_k 为 Beta 分布低分位数，例如10%分位。它是模型内可信下界，不是已验证的真实掌握率。

只有 l_k≥τ 才把该知识点计作可跳过；初始候选 τ=0.7，在开发集决定后冻结。必须用真实题目检查该门槛是否过度保守。重复打开、阅读或同题重答不能当独立证据叠加；跨项目只迁移相同概念证据，并用新题确认；不宣称复杂知识追踪效果。

### 4.3 受约束路径规划

构造目标反向前置闭包，按用户门控去除已可靠掌握概念。每个候选单元的增量成本包括当前尚未满足的前置闭包成本；共享前置只计一次。允许多个材料覆盖同一概念，避免“所有目标只有一条链”导致优化问题退化成排序。

首个可复现目标：

`J(P|U)=Σ c(v,U)+λ Σ duplicated_concept(v)+γ Switch(P)`

约束：目标必需概念全部有学习或证据覆盖；硬前置在对应单元前满足；成本≤B。`Switch`只在重规划中计剩余路径改变，建议用保留单元的相对顺序逆序数加新增单元数，先归一化。

成本候选：`c(v,U)=c0(v)×[1+α×mean(1-m_k)]`。c0 来自源码长度、依赖深度等可解释特征；无真实标签时固定少量开发集参数，不拟合大模型。

求解器：确定性的闭包增益/成本贪心作为强基线；候选主方法用 beam search 在可行单元中搜索并去重状态，排序与平局规则固定。默认候选上限50、beam宽16，开发集测宽1/4/16/32；这些是初始计算预算，不是最优参数。微型图用穷举/动态规划校验可行性与代价差距。不得称全局最优或宣称近似保证。

必须区分：经小图精确求解证明无解的 `INFEASIBLE_PROVEN`；启发式未找到方案的 `NO_FEASIBLE_FOUND`；搜索超时的 `TIMEOUT`；合法方案 `FEASIBLE`。对启发式失败不能声称数学不可行。可返回明确标注未覆盖项的部分建议，但不得记为任务覆盖成功。

### 4.4 候选创新机制：诊断是否值得

对临近目标、掌握状态不确定且重学昂贵的知识点 k，比较：

`VOI(k)=J*(U)−[c_quiz(k)+p_pass×J*(U_pass)+(1−p_pass)×J*(U_fail)]`

J*表示同一个预算受限规划器的估计成本，包含切换惩罚；p_pass仅来自开发数据校准或明确标注的先验，不能用最终题答案估计。分支超时或无法评估时保守补学，不把失败值当零。两分支均需考虑剩余预算。

仅在 VOI>ε 且测验预算允许时选最高值诊断；否则直接补学。每天项目测试中必须计入诊断耗时，不能免费获得画像。候选门槛、最大测验次数在开发集固定。小样本下该机制可能不如固定测验；通过“固定频率测验、相同测验预算”的对照隔离选择策略价值。

### 4.5 重规划

学习后以独立短题更新状态，对剩余任务局部重算。保留已完成项、记录触发证据、前后路径、增加的内容与原因。变化惩罚只能减少无意义切换，不能阻止补齐未满足的硬前置。最大重规划次数和总时间纳入预算。

主循环：获取证据 → 构造缺口闭包 → 求候选路径 → 判断诊断/补学 → 收集反馈 → 更新证据 → 修复剩余路径 → 独立终测。终测在学习阶段不可访问。

## 5. 五个模块与简化决策

| 模块 | 提交前完整交付 | 可检验的适配点 | 简化条件 |
|---|---|---|---|
| 代码认知图 | Python静态关系、经审核教学依赖、源码定位 | 来源分层，防止把调用边误当先修边 | 语义边错多就降为候选，不扩充图数据库 |
| 成本估计 | 静态代理成本；有训练数据才校准 | 用户缺口影响增量闭包成本 | 预测差就只报告代理量，不硬称认知时间 |
| 能力与记忆 | 短测、证据ID、动态更新、持久化、两个项目概念映射演示 | 证据门控跳过，跨项目再验证 | 不上深度知识追踪；跨项目仅做案例，不能宣称泛化提升 |
| 主规划器 | 基线、约束搜索、诊断/反馈机制、不可行状态、可复现实验 | 预算内诊断与补学决策、局部路径修复 | 无收益机制移除，但保留真实路径对照 |
| Issue推荐 | 真实链接、抓取时间、模块相关性、技能缺口、准备步骤 | 用已验证学习成果匹配候选任务 | 无独立标签时只展示案例，不报告NDCG提升 |

Issue不足的仓库可与另一个仓库的案例分开展示；不能拿已关闭Issue伪装当前可参与任务。没有合适项就说明原因。提交PR和社区互动不作为闭环完成的必要条件。

## 6. 工程结构与接口冻结

先用 Python、AST、NetworkX/普通邻接表、SQLite、Streamlit 与 pytest；依赖版本D01实测锁定，不提前承诺某版本。语义解释可接一个可替换模型接口，先缓存固定仓库内容；模型本身不是主算法。核心规划与离线复现不依赖外部API实时可用。

建议目录：`src/codecompass/{graph,learner,planner,retrieval,issues}`、`app/`、`tests/`、`benchmarks/`、`configs/`、`scripts/`、`results/raw/`、`results/figures/`、`docs/`。用户数据与密钥不进入 Git。

D01冻结的数据契约：
- RepoSnapshot：url、commit、license、retrieved_at、hash。
- LearningUnit：id、source_spans、concept_ids、prerequisites、provenance、base_cost。
- LearnerEvidence：pseudonymous_user_id、concept_id、item_id、outcome、timestamp、project、evidence_type。
- PlanningRequest：snapshot_id、task_id、learner_state、budget、cost_unit、config_version。
- PlanResult：status、ordered_units、coverage、unmet_constraints、estimated_cost、reason_trace。
- ExperimentEvent：run_id、actor、code_commit、data_hash、config_hash、timestamp、event_type、payload。

先保留结构化JSON样例，再由双方分别实现，禁止独立修改共享接口导致无法集成。
